# genshin-uncap V1 行为规格

状态：用户已批准行为方案，实现与验证按 [tasks.md](tasks.md) 分阶段记录

## 目标与边界

使用一个 Windows x64 Rust EXE，在用户当前 Steam／dwproton／prefix 启动链中启动 `YuanShen.exe`，从外部定位并周期检查 FPS 变量，仅当前值与目标不同时覆盖，目标 FPS 在本次运行期间固定

V1 的“停止覆盖”仅指工具不再写入，不写回旧值、不恢复游戏当前设置、不承诺最后写入的值立即失效；游戏何时重写该变量由游戏决定

V1 不提供热键、运行时开关、FPS 加减、托盘、attach、注入线程、DLL、shellcode、自动更新、遥测或进程隐藏，不增加驱动、权限提升或反作弊绕过

## 已确认决策与接口

```text
genshin-uncap.exe --game <游戏 EXE 路径> [--fps <整数>] [-- <游戏参数…>]
genshin-uncap.exe --probe --game <游戏 EXE 路径> [-- <游戏参数…>]
```

- REQ-001：`--game` 必填，`--fps` 默认 `120`，有效范围为 `1..=120`，遵守用户明确的写入上限 120，超限、解析或路径错误在启动游戏前报告
- REQ-002：保留 Unicode 路径和逐项参数，`--` 后参数只传给游戏，工作目录为游戏 EXE 所在目录，沿用现有 runner、prefix 和 Steam 环境
- REQ-003：每次只控制本次启动得到的子进程句柄，不连接已有游戏，不复用跨启动 PID 或地址，重复控制器或目标游戏已运行时明确拒绝
- REQ-004：目标 FPS 仅有一个不可变来源，程序成功定位和验证地址，并在初始化期限内只读观察到有效值稳定 500 ms 后，才能开始周期控制，日志区分启动、定位、控制和失败阶段
- REQ-005：初始化等待最多 60 秒，期间检查游戏是否退出；模块未就绪可以在期限内等待，已确认的地址歧义、越界、权限或读写错误立即失败
- REQ-006：每次写入完整 4 字节，并检查 Win32 返回值与实际字节数；无匹配、候选歧义或不完整可访问范围均不写入
- REQ-007：保留控制台，Ctrl+C、关闭控制台、崩溃或强制结束工具后停止覆盖，不恢复任何值且不终止游戏；游戏退出后工具退出
- REQ-008：启动、定位或读写失败时终止控制器流程，报告阶段和可用的 Win32 错误；工具已启动的游戏保持运行
- REQ-009：`--probe` 是开发诊断入口，仍只启动新游戏，完成目标身份、模块与候选检查后打印诊断并退出，绝不写游戏内存，游戏继续运行
- REQ-010：固定每 500 ms 读取并校验页面、定位指令和 FPS 值，仅当前值与固定目标不同时调用写入；值相等时仍执行全部检查，不承诺性能收益，不引入运行时自适应周期
- REQ-011：不增加前后台、菜单或过场识别，记录这些场景的实际限帧表现；不能把成功写内存或打印成功当作实际 FPS 验证
- REQ-012：保留当前 Steam、dwproton、prefix 和 BetterGI 流程，完成真实基础验收且用户明确授权后，备份并替换旧解锁器调用以测试完整链，保留回退文件；本轮接入已获明确授权，未覆盖的兼容场景继续单列记录

行为已经明确，不再把附件中较早的“恢复默认”、运行时 toggle 或进程内 worker 建议作为当前需求；外部写入已在本机120FPS限定场景得到验证，完整兼容范围仍按任务表逐项验收

## 状态与失败行为

主流程为 `解析 → 重复启动检查 → 启动 → 定位与验证 → 覆盖 → 退出`，探针在定位与验证后直接退出；任何阶段失败进入带错误的退出路径

停止信号只使主循环退出，控制台处理函数不修改 FPS、不恢复值、不终止游戏；强制终止工具也不存在留在游戏内继续写入的代码

通过独立游戏控制台或等价的控制台隔离保持游戏生命周期独立，必须用实际 Ctrl+C 和关闭窗口验证隔离结果，不能只凭创建标志认定通过

特征失效、目标不可信、权限不足或外部方案不满足真实验收时停止并记录证据，不自动换特征、换 runner、换 prefix、注入或降低“停止覆盖”的定义

## 验收标准

| 编号 | 关联要求 | 通过条件 |
| --- | --- | --- |
| AC-001 | REQ-001 | 默认、边界值、非法整数、缺参数和未知参数行为明确，非法调用不启动游戏 |
| AC-002 | REQ-002、REQ-003 | 假目标实际收到中文、空格、空参数和引号参数；重复工具与已有游戏被拒绝；不连接错误 prefix 中的同名进程 |
| AC-003 | REQ-005、REQ-006 | 扫描覆盖末尾、等长、超长和跨块；畸形 PE、缺节、负位移、溢出、部分读写、保护异常与多候选均有有界结果，不误写 |
| AC-004 | REQ-004、REQ-005、REQ-008 | 模块迟到可在时限内就绪，初始化超时和游戏早退正确退出，失败不打印覆盖成功，不杀已启动游戏 |
| AC-005 | REQ-009 | 真实 Proton 只读探针记录 runner、prefix、游戏 build、模块和候选证据，执行路径不请求写入且不调用写内存 |
| AC-006 | REQ-004、REQ-010、REQ-011 | 批准的写入试验覆盖登录、游戏、菜单、垂直同步开／关、传送、加载、过场和最小化；在性能足够的重复场景用帧率观测证明效果，完成至少 30 分钟覆盖试验 |
| AC-007 | REQ-007、REQ-008 | 假目标验证工具退出后无后续覆盖；真实环境分别验证 Ctrl+C、关窗口、强制结束工具和游戏先退出，不连带结束游戏，完成至少 3 次启动／退出循环 |
| AC-008 | REQ-003、REQ-007 | 游戏重启不复用旧地址、句柄或控制状态，不产生两个并发写入者 |
| AC-009 | REQ-010、REQ-012 | 记录产物大小、imports、控制器内存、CPU、唤醒频率及启动耗时，按 REQ-012 安装到既有启动链并验证启动、游戏表现与退出 |

测量记录必须带构建版本、命令、runner、prefix、场景、持续时间和实际数值；V1 不预先承诺任意体积或零开销，也不承诺硬件不足时达到目标 FPS
