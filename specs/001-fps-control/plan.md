# V1 实施设计

## 选型与门槛

生产候选方案是 Windows x64 外部控制器，使用 Rust 标准库及按需启用功能的 `windows-sys`；已完成本机120FPS限定验证，完整场景和现有启动链接入尚未完成验收，保留旧启动脚本

不增加异步运行时、通用 hook 框架、多后端接口或配置文件，模块仅按纯逻辑与 Win32 边界拆分；无 DLL、远程线程或进程内残留代码，因此控制器退出后没有独立执行主体继续覆盖

## 启动与生命周期

- 解析 `--game`、`--fps`、`--probe` 和 `--` 参数，路径使用 OS 字符串，使用标准库的 Windows 参数编码逐项转发，不手工拼接命令行
- 启动前拒绝重复控制器和已运行目标，启动得到的进程句柄是本次唯一身份，按句柄取模块，不连接同名旧进程，不把 Linux PID 当 Win32 PID
- 保留原 Steam、Proton、prefix 和 BetterGI 环境，将游戏工作目录设为 EXE 目录，采用独立控制台隔离游戏与工具的控制台关闭事件
- 主线程完成启动、定位、覆盖与退出，控制台处理函数仅设置原子停止信号；所有句柄通过作用域释放，不对游戏使用 kill 或终止 API
- 初始化最多等待 60 秒并持续观察子进程状态，模块未出现时有界重试；已确认的结构错误、候选歧义或权限错误立即报告，不将确定失败吞成无限重试
- 探针只以读取所需权限访问游戏，输出身份、模块和候选证据后退出；生产模式启动时请求写入所需权限，验证通过后才使用写入 API

## 读取、定位与写入

- 逐字段解析 DOS、NT、AMD64／PE32+ 和节表，检查头部、节数、实际 optional header 长度、模块范围与算术溢出，只读取扫描所需节区
- 以 `VirtualQueryEx` 结果约束读取，对 committed、可读且连续的区域分块扫描，跨块保留最多 pattern 长度减一的尾部，不跨不可读空洞拼接候选
- 模式扫描使用安全切片覆盖全部合法起点，解析带符号 RIP 位移并检查溢出，收集所有候选后验证指令与目标一致性，存在不同有效目标时拒绝
- 目标必须在预期模块范围，完整 4 字节位于合法 committed 可读写区域，读取和写入均要求 Win32 成功及字节数完整；不能单凭初值或页保护通过语义验证
- 实测初始化时候选值先为 `-1`，随后变为 `60`；在同一 60 秒期限内只读等待 `1..=120` 的值稳定 500 ms 后才允许写入，初始化未知值不覆盖，运行中出现未知值立即停止
- 固定目标值只由主循环周期写入，游戏退出或停止信号立即结束循环，读写失败报告阶段后退出，所有出口均不恢复旧值、不终止游戏
- 初始 500 ms 周期为实验参数，只在真实试验不满足验收时依次评估 250、100、50 ms，最终提交通过验收的最慢固定周期，不引入运行时回退策略

## 构建与验证

默认目标沿用 `x86_64-pc-windows-gnu`，使用隔离工具链补齐 Windows 标准库和 MinGW，保留系统已有 Rust；release 配置为 `opt-level = 3`、`lto = "fat"`、`codegen-units = 1`、`strip = "symbols"`、`panic = "abort"`

保留通用 x86-64 CPU 和默认 dev 配置，不添加 `target-cpu=native`、nightly、PGO 或标准库重编译；`abort` 终止的是独立控制器进程，且不执行栈展开清理

验证顺序为清单解析和宿主纯逻辑测试、Windows 交叉构建、自建 Windows 假目标、真实 Proton 只读探针、限定写入试验、30 分钟及退出循环；每一层独立记录，不跨层推导兼容结论

性能记录 EXE 字节数、imports、控制器内存、CPU、唤醒频率和启动额外耗时，真实 FPS 采用环境现有可重复观测工具，记录场景与硬件瓶颈，不以内存值替代实际帧率

## 接入与回退

真实验收通过后备份现有批处理，只替换旧解锁器调用为显式游戏路径和 `--fps 120`，保持 runner、prefix、Steam 环境和 BetterGI 调用不变

真实环境缺失、无法独立验证地址或外部方案失败时保留当前启动链，相关任务标记 `BLOCKED` 并给出准确复现命令，不以未通过的程序替换旧工具，不自行改成注入方案
